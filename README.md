# astro-cloudflare-resource-urls

An Astro integration that normalizes local resource URLs for Cloudflare Static
Assets. It turns `@` into `%40` and avoids the extra canonical-path redirect.

The integration runs on the finished static build artifact, so the same URLs work
when deploying that artifact to Cloudflare, GitHub Pages or nginx.

## Astro

```js
import { defineConfig } from 'astro/config';
import resourceUrls from 'astro-cloudflare-resource-urls';

export default defineConfig({
  site: 'https://example.com',
  integrations: [
    // Other integrations, including output compression, go first.
    resourceUrls(),
  ],
});
```

No `site` is required for relative URLs. If configured, same-origin absolute URLs
are normalized too. External URLs are left alone. The immutable asset directory
defaults to Astro's `build.assets`.

Options:

```js
resourceUrls({
  site: 'https://example.com', // Overrides Astro's site.
  assetsDirectory: 'bundles', // Overrides Astro's build.assets.
  exclude: (file) => file.startsWith('third-party/'),
});
```

`exclude` skips processing a file's contents; its filename still participates in
resource lookup. Paths passed to `exclude` are relative to the output directory.

## Extension handlers

The handler registry decides both which files to read as UTF-8 and how to parse
those files. Built-ins cover `.html`, `.css`, `.js`, `.mjs`, `.cjs`, `.json`,
`.webmanifest`, `.svg` and `.xml`. Other extensions are left untouched.

Add a format, reuse a parser, override a built-in, or disable it:

```js
import resourceUrls, { resourceUrlHandlers } from 'astro-cloudflare-resource-urls';

resourceUrls({
  handlers: {
    '.json': false, // Do not interpret arbitrary JSON strings as URLs.
    '.htm': resourceUrlHandlers.html,
    '.custom-js': resourceUrlHandlers.javascript,
    '.refs': (source, { rewrite }) =>
      source.replace(/^resource=(.*)$/gm, (_, url) => `resource=${rewrite(url)}`),
  },
});
```

Handler keys include the leading dot and are case-sensitive. The callback receives
`{ file, rewrite, withBase }`: `file` is the raw path relative to the output root,
`rewrite(url)` resolves a ready URL relative to that file, and `withBase(base)`
returns a resolver for a document-specific base. Only pass actual URL fields to
these functions; parse and serialize the format using an appropriate parser.

Handlers are synchronous and must be deterministic: they may run more than once
while immutable filenames and dependent references are updated. Use the provided
resolver so dependencies participate in that process. Disabled files still exist
in the resource manifest and can be referenced by other files.

The generic JSON handler examines all string values. Matching an output filename
does not establish that a string is a URL; disable or replace it for structured
application data. The same applies to arbitrary XML text. These parsers remain
available for compatibility, but should be enabled only for suitable data.

## Raw filenames are not URLs

Use `filePathToUrl()` when the input is an exact filename from the filesystem
or a file listing. It encodes every path segment **without decoding**:

```js
import {
  filePathToUrl,
  encodeResourceUrl,
  createResourceManifest,
} from 'astro-cloudflare-resource-urls/url';

filePathToUrl('/images/image@2x.png'); // /images/image%402x.png
filePathToUrl('/images/image%402x.png'); // /images/image%25402x.png
filePathToUrl('/images/a?b#c.png'); // /images/a%3Fb%23c.png

// A ready URL already gives percent escapes their URL meaning.
encodeResourceUrl('/images/image%402x.png'); // /images/image%402x.png
encodeResourceUrl('/images/image%25402x.png'); // /images/image%25402x.png
encodeResourceUrl('/images/image@2x.png?q=@#@'); // /images/image%402x.png?q=@#@

const resources = createResourceManifest(['/images/image@2x.png', '/images/image%402x.png']);
resources.get('/images/image@2x.png'); // /images/image%402x.png
resources.get('/images/image%402x.png'); // /images/image%25402x.png
```

`filePathToUrl()` accepts a URL-style path with `/` separators, not a complete URL.
Literal `?` and `#` belong to the filename and are encoded. Append a query or
fragment _after_ creating the URL. Raw-file encoding is deliberately not
idempotent; ready-URL normalization is idempotent.

An asset URL already generated by an Astro/Vite import is a ready URL, not a raw
filename. Use `encodeResourceUrl()` for it.

The integration treats existing HTML/CSS/JS references as **ready URLs**. It does
not guess whether `%40` was intended as a literal filename substring. If both
`image@2x.png` and `image%402x.png` exist, `/image%402x.png` points to the first;
the second must be referenced as `/image%25402x.png`. Generate references from
exact filenames using `filePathToUrl()` or `createResourceManifest()`.

The `/url` entry point has no dependencies and is safe to import in browser code.

## Supported output

- HTML, SVG and XML resource references, including responsive image candidates,
  model posters/environment maps and preload sources.
- Inline/external CSS, `url()`, `@import`, `image-set()` and custom properties.
- Static JavaScript strings and expression-free templates, including inline preload.
- JSON and web manifests.
- Immutable asset names, transitive/cyclic dependencies and Subresource Integrity.

Only references resolving to actual output files are rewritten. Unrelated markup
is preserved through source-range patches. Queries, fragments, data URLs and
foreign URLs are preserved.

## Limits

- URLs assembled from runtime expressions need an explicit helper call. Choose
  `filePathToUrl()` for raw filenames or `encodeResourceUrl()` for ready URLs.
- This operates on static build output, not the dev server or SSR responses.
- Source maps on changed immutable assets currently cause a build error rather
  than silently publishing invalid maps.
- XML uses HTML source locations; general XML namespaces and schemas are not
  validated. Test specialized feeds before enabling transformation on them.
- The Astro peer range accepts 6 and 7; the integration is currently tested on 7.2.9.

You can also process an existing output directory directly:

```js
import { normalizeResourceUrls } from 'astro-cloudflare-resource-urls';
await normalizeResourceUrls('./dist', { site: 'https://example.com' });
```

## Automatic npm publication

The GitHub Actions workflow `.github/workflows/check.yml` runs checks on pushes
and pull requests. A push to `main` publishes the checked tarball to npm without
rebuilding it. An existing version is skipped. Stable versions use `latest`;
versions containing a prerelease suffix use `next`.

Publication uses **npm Trusted Publishing (OIDC)**, without an `NPM_TOKEN` secret.
Bun installs, checks and packs the package. Only the registry publication uses
npm CLI 12.2.0, launched through `bunx`, for its native OIDC support. The separate
publish job has `id-token: write`; the check job has no OIDC permission.

In npm's package settings, add a GitHub Actions trusted publisher with:

| Field                | Value                                                         |
| -------------------- | ------------------------------------------------------------- |
| Organization or user | `jag-k`                                                       |
| Repository           | `astro-cloudflare-resource-urls`                              |
| Workflow filename    | `check.yml`                                                   |
| Environment name     | Leave empty; this workflow does not use a GitHub environment. |
| Allowed actions      | Enable direct publication (`npm publish`).                    |

The workflow filename is just `check.yml`, not its full path. Push the workflow
to the repository before configuring the publisher. This workflow runs on
GitHub-hosted runners, as required by npm. The package's `repository.url` already
matches `jag-k/astro-cloudflare-resource-urls`.

If npm does not yet have this package, create it with an initial authenticated
publication before configuring the publisher in its package settings. This is a
one-time bootstrap, not an Actions secret requirement. A new trusted publisher
configuration must complete its first successful publication within two days;
if the bootstrap version is already published, bump the version before running
this workflow so it performs a publication instead of skipping it.

For later releases, update `version` in `package.json` and push to `main`.
The workflow can also be run manually on `main` to retry a failed publication.
Other branches and pull requests only run verification. Public packages published
from public repositories through OIDC receive npm provenance automatically.

Reference: [npm Trusted Publishing for GitHub Actions](https://docs.npmjs.com/trusted-publishers/#for-github-actions).

## Development

```sh
bun install --frozen-lockfile
bun run check
bun pm pack
```

The pack step builds JavaScript and TypeScript declarations. The tarball includes
only `dist/`, this README, the MIT license and package metadata. Creating a tarball
does not publish to npm.
